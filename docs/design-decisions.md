# 设计取舍

本说明从已有使用说明、历史评审、项目梳理和当前实现提炼；不把规划中的投放复盘能力写成已经运行的业务系统。

| 问题 | 当前选择 | 收益与代价 |
|---|---|---|
| 一条提示词同时做所有任务，判断和输出难以追踪 | 三个主流程、八个专项、一个独立机制分析工具 | 任务边界清楚；完整诊断需要读取多份规范 |
| 不同专项各自抽帧，时间点和证据容易错位 | 共用 Python 预处理、mapping 和公共规范 | 建议能回到具体画面／台词；需要 ffmpeg 与本地文件权限 |
| 直接阅读高分辨率全视频成本难控制 | 全片、字幕对齐、开头三层采样，默认帧宽 540 | 减少重复输入；运动连续性、小字和音频听感仍有限制 |
| 模型容易把“看不到”当成“没有” | 检查项缺证据与整维 N/A 分开；审核有待补证据状态 | 保留已知结论，又不掩盖未知；有时需要用户补材料 |
| 重跑时旧文件仍在，容易误用 | 新帧验证后替换；只读本轮 JSON 和 mapping 指向的产物 | 保留历史文件；消费者必须遵守有效产物边界 |
| 经验解释容易变成效果承诺 | 行为科学用于生成可检验假设；比较设计与效果验证分开 | 表述可核实；不能仅凭内容分数宣布某机制有效 |
| 固定方向数量可能超过视频预算 | 先预留条数并核算 cell；不够则缩小范围或改 A/B | 方案不超预算；减少方向要经过用户确认 |

## 已实现与后续工作

当前可交付的是指令包、预处理脚本、文件接口与示范产物。S/T/H 标签用于区分策略、技巧和开场；它们不是自动归因模型。

后续有真实样本时，可记录素材、脚本版本、达人、执行偏差、发布条件和同口径结果，做人工复核与小规模比较。在这些数据存在之前，不对播放、转化、ROI 或节省工时作数值承诺。
