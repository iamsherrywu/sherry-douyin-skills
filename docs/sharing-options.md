# 面试作品的分享方式

核对日期：2026-11-27。本项目用于 AI Transformation Intern 面试作品展示，采用完整版公开的分享方式。

## 当前公开范围

仓库包含作品概览、流程图、AI 与人的分工、合成案例和截图，以及完整 Skill、脚本、测试与可编辑交付。首页先解释业务与产物，安装和技术复核后置。真实商业资料、上级私人源文档、本地会话和运行环境不在公开范围内。

| 方式 | 优点 | 需要接受的取舍 |
|---|---|---|
| 完整仓库公开 | 技术细节与复现材料直接可见 | 任何人可访问和 fork；版权声明不是技术访问限制 |
| 全部私有 | 由所有者控制仓库访问 | 直接发链接不会给面试官权限；需额外协调账号与访问 |
| 展示目录公开，完整实现私有 | 阅读入口便捷，控制公开内容范围 | 维护两份材料；公开部分本身仍可被保存 |

本仓库选择第一种方式，同时保留「仅作品展示，复用另行授权」的声明。公开访问与开源许可是不同概念；允许看见文件，不表示授予不限范围的复用许可。

## 几个容易混淆的边界

- GitHub 的公开仓库对互联网可见，私有仓库只对获准者开放；不能把私有链接当成任何人可直接阅读的作品链接。[仓库可见性](https://docs.github.com/en/repositories/creating-and-managing-repositories/about-repositories)
- 公开后别人能 fork；以后转回私有，不会使已有公开 fork 自动私有。保留版权可以表达授权范围，不能阻止别人先读到内容。[可见性变更](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)
- 个人私有仓库的 collaborator 不是只读权限，而是读写权限。不必为了让 HR 看介绍就邀请其成为协作者；可先分享展示材料，技术复核另行安排。[个人仓库权限](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/repository-access-and-collaboration/permission-levels-for-a-personal-account-repository)
- GitHub Pages 与仓库权限是不同层面的设置，私有源仓库不自动意味着网页私有。当前无需先搭建网页，用展示仓库 README 即可提供阅读入口。[Pages 发布来源](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## 面试时如何使用

简历可使用仓库首页链接；初次沟通用概览和一份案例解释流程；技术追问时展开实现、证据接口、规则和测试。关于个人贡献，按实际经手环节说明，并主动交代 AI 辅助的部分，不把原型说成企业上线项目。
