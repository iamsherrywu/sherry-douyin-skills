# 诊断专项公共规范

本文件是 8 个诊断专项（kaitou / wanbo / like / comment / fav / share / shijue / wenzi）共用的规则。专项 SKILL.md 只写维度特有的内容；凡是本文件已有的，专项不再重复。无论专项是被 `/sherry-douyin-review` 作为子 Agent 调用，还是被用户单独调用，都遵守本文件。

---

## 1. 输入：你会拿到什么

素材由 `sherry-douyin-review/scripts/prepare_video.py` 统一生成，位于一个**过程目录**（形如 `outputs/{标题}/过程文件_{hash8}/`）：

| 文件 | 内容 | 怎么用 |
|---|---|---|
| `summary.md` | 时长、分辨率、字幕条数、帧数、镜头统计、完整逐字稿、建议先看的帧 | **先读这个** |
| `mapping.json` | `frames[]`：每张帧的 `time`、`file`、`layer`、`srt_index`、`text`；`cues[]`：全部字幕 | 定位"第 X 秒画面是什么、当时在说什么" |
| `L1_{sss}s.jpg` | 全片每秒 1 帧 | 看节奏、看全局 |
| `L2_asr_{nn}_{t}s.jpg` | 每条字幕起止时刻的帧（长句每秒补一张） | 看"说这句话时画面是什么" |
| `L3_head_{t}s.jpg` | 0–3 秒每 0.5 秒一帧 | 看开头 |
| `asr.srt` | 字幕副本 | 一般不用直接读，`summary.md` 里有全文 |
| `scenes.json` | 镜头切换点和每个镜头时长（可能没有） | 看节奏、看镜头长度 |
| `media.json` | 时长、分辨率、帧率、有无音轨、SHA256 | 一般不用直接读 |

间隔小于 0.3 秒的帧已去重，所以某一秒的 L1 可能被同时刻的 L2/L3 取代——按 `mapping.json` 的 `time` 找帧，不要按文件名猜。

**只用本轮有效产物。** 过程目录会保留旧文件，文件存在不代表本轮生成。帧只读本轮 `mapping.json.frames` 列出的文件，不用通配符把旧图混进来；逐字稿以本轮 `cues` / `summary.md` 为准。预处理成功返回的 JSON 中 `scenes` 或 `srt` 为 null 时，不读取目录里遗留的同名文件。主 Agent 要把这两个字段传给专项；若只拿到过程目录，先读 `summary.md`，本轮未记载镜头统计就不读 `scenes.json`。`--l1-step` 最小为 0.3 秒，与去重间隔一致。

**单独调用（没有过程目录）时**：先运行

```bash
python3 {本套装路径}/skills/sherry-douyin-review/scripts/prepare_video.py 视频.mp4 [--srt 字幕.srt] [--transcribe] [--scenes]
```

再从它输出的 `work_dir` 开始。专项自己**不写 ffmpeg 命令、不另行抽帧**。

**只有文案、没有视频时**：可以做文案层面的判断，但每个涉及画面的结论都写"视觉未提供，无法判断"，不要推测画面。

### 主 Agent 附带的信息

被 review 调用时，prompt 里还会有：**画面描述摘要**（主 Agent 亲眼看过关键帧后写的各时段一句话描述）和**防幻觉检查点**（"全片没有 XX 场景"）。把它们当作基准：如果你读到的帧与摘要严重不符，停下来报告"帧与摘要不符"，不要继续诊断。

### 该读多少帧

按维度需要读，不必全读：

- 开头（kaitou）：L3 全部 + 前 3 秒的 L2
- 视觉传达、文案（shijue / wenzi）：全部 L2，必要时补 L1
- 完播（wanbo）：全部 L1 + `scenes.json`，弃看点附近补 L2
- 点赞 / 评论 / 收藏 / 转发：按逐字稿先定位关键句，再读对应的 L2；结尾段必读

一次 Read 多张帧，减少往返。

## 2. 证据边界：只判断你能看到的

子 Agent 只有**帧图片 + 逐字稿**，没有声音、没有连续画面、没有账号数据。因此：

| 不要判断 | 原因 | 怎么写 |
|---|---|---|
| 音量、静音、BGM 情绪、音画延迟、环境噪音 | 听不到 | 「音频无法判断」 |
| 小于 1 秒的停留时长、字号差"10%"这类精确量 | 1 fps 抽帧和缩放后的图分辨不出 | 用「约 X 秒」「明显更大 / 看不出差别」 |
| 粉丝量、账号属性、当前流行趋势 | 没有数据 | 不作为扣分依据；用户给了再用 |
| 真实完播率、留存曲线、评论区实际温度 | 没有数据 | 写"预判"，不写"用户在第 X 秒流失" |
| 中文词性统计（"名词 X 个、形容词 Y 个"） | 不可复现 | 改为点名具体的空泛词和具体词各举 2–3 例 |
| "我的手指会不会动""3 秒内想不想到某个人" | 自省不可复现 | 改为陈述证据：有没有具体的人群标签 / 有没有可转述的一句话 |

没有证据的地方写**「无法判断」**，不编。

**检查项未知与维度不可评分分开处理。** 个别检查项无法判断，但核心证据足以确定基础分时，可以评分并列出未核实项；如果连本维度的核心内容都无法核实（例如没有可读文案时评文案精度），该维度输出 **N/A（证据不足）**，不猜分，也不记成 0 分、1 分或「弱」。

## 3. 评分：统一尺子

所有维度用同一套规则，这样 review 才能横向比较。

### 分数含义

| 分 | 含义 |
|---|---|
| 1 | 这个维度完全没有设计，或有致命错误且全片没有任何补救 |
| 2 | 有致命错误，但其余部分有可用的设计；或没有致命错误但有 2 条以上严重错误、机制几乎未激活 |
| 3 | 没有致命错误，至少激活 1 个机制，执行有明显瑕疵 |
| 4 | 1–2 个机制清晰激活、执行到位，瑕疵不影响效果 |
| 5 | 多个机制互相增强，执行精准，找不到需要改的地方 |

### 计算顺序

1. **致命错误 → 上限 2 分。** 致命错误是"只要存在，这个维度就基本失效"的问题，每个专项列出自己的致命错误清单。
2. **严重错误 → 每条扣 0.5 分**，专项可对个别错误标注扣 1 分。**总分下限 1 分**，不会出现 0 分或负分。
3. **机制激活数量和执行质量**决定基础分落在 3 / 4 / 5。
4. 加分项只在没有致命错误时生效，且总分不超过 5。
5. 结果保留到 **0.5**（如 2.5 / 5）。不要进位成整数。

### 分档建议的边界

改进建议按分数分三档，边界明确：**≤ 2**（先修错误）、**2.5–3.5**（补机制）、**≥ 4**（打磨与叠加）。

## 4. 输出：两种模式

### 子 Agent 模式（被 review 调用时**只输出这个**）

```
## {维度名}：X / 5 或 N/A（证据不足）

**一句话**：{直接给结论}

**致命错误**：{无 / 逐条：错误名 —— 第 X 秒具体表现}
**严重错误**：{无 / 逐条：错误名 —— 第 X 秒具体表现（-0.5）}

**关键发现**（2–3 条，每条带时间点和证据）：
1. 第 X 秒：{看到什么 / 说了什么} → {意味着什么}
2. …

**最重要的改进**（1 条）：
- 第 X 秒（或 X–Y 秒）：{具体操作}。{为什么——1 句}【剪辑改 / 需要补拍】

**无法判断**：{列出因证据不足而跳过的检查项；没有就写"无"}

**维度特有数据**：{专项要求回传的结构化字段，见各专项"回传字段"一节；没有就省略}
```

控制在 **40 行以内**。不输出完整报告，不重复素材信息。

维度为 N/A 时，只保留已知事实、无法判断的原因和需补充的材料；不强凑关键发现、错误或修改指令。

### 完整模式（用户单独调用时）

在子 Agent 模式的基础上，追加专项定义的"详细分析"段（通路/机制表、逐段表等）和分层改进建议。结构见各专项。

## 5. 判断原则

- **按证据打分，不预设结论。** 开头没有留人设计就写没有；有就写有。既不硬找亮点，也不为了显得严格而压分。
- **每个结论落到时间点和画面/台词。** 不说"开头不太好"，说"0.0–1.0 秒是泳池远景，画面中心没有主体，字幕未出现"。
- **改进建议读完就能干活。** 写到"把第 6 秒的清单卡剪到开头，字幕改成『…』"这个粒度。
- **区分内部版和给拍摄方的版本。** 子 Agent 输出是内部版，可以用机制名词；但"最重要的改进"那一条要写成拍摄方能直接执行的大白话，因为 review 会原样放进修改指令。

### 修改建议中不出现的词

建议优化 / 建议提升 / 增加信息密度 / 触发损失厌恶 / 激活社交货币 / 制造认知缺口 / 峰终定律 / 系统 1、系统 2 / 变动奖赏 / 禀赋效应 / 双编码 / 加工流畅性 / 认知负荷 / 视觉显著性 / 具身模拟 / 模态契约 / 知识的诅咒，以及任何行为经济学、传播学、语言学术语。把它们翻译成"画面跟说的内容对不上""字幕看不出哪几个字是重点""这句话听完脑子里想不出画面"。

---

## 6. 语言

用户用中文就用中文，用英文就用英文。中文排版遵循《中文文案排版指北》（中英文之间加空格，全角标点）。
