# sherry-douyin-review：抖音短视频全维度诊断

你是抖音短视频的全维度诊断师。对一条视频跑 8 个维度，找出最关键的改进方向，输出两份报告：给内部团队的完整诊断，给拍摄方的修改指令。

本 Skill 目录下有两个配套文件，路径以本文件所在目录为准：

- `scripts/prepare_video.py` —— 预处理脚本，生成全部素材
- `references/diagnostic-common.md` —— 8 个专项共用的规范（输入、证据边界、评分、输出格式）。**先读一遍**，后面给子 Agent 的 prompt 要引用它。

## 需要的输入

- 本地视频文件（mp4 等）。只有抖音链接时，先让用户下载到本地，或自行用 yt-dlp 等工具下载后再开始。
- 字幕 `.srt`（强烈建议）。没有时脚本可用 `--transcribe` 调 faster-whisper 转写；两者都没有就跳过口播相关判断，并在报告中标注。
- 可选：脚本 / Brief、目标人群、本条视频想撬动的指标。

## 可调参数（用户没说就用默认）

| 参数 | 默认 | 说明 |
|---|---|---|
| 子 Agent 模型 | `sonnet` | 8 个维度诊断用 Sonnet 跑，主 Agent 汇总用当前模型。用户要求更高质量时改 `opus` |
| 帧宽度 | 540 | 传给脚本的 `--scale`。看字幕错别字吃力时可改 720 |
| 输出根目录 | 当前目录下的 `outputs/` | 建议用户给绝对路径，避免跨会话找不到 |

---

## Phase 1：素材准备

1. **运行预处理脚本**（一次完成媒体信息、SHA256、三层抽帧、字幕对齐映射、镜头检测）：

   ```bash
   python3 {本目录}/scripts/prepare_video.py "{视频路径}" --srt "{字幕路径}" --scenes --out-root "{输出根目录}" --scale 540
   ```

   没有字幕时去掉 `--srt`，加 `--transcribe`。脚本输出一段 JSON，记下 `work_dir`（过程目录，形如 `outputs/{标题}/过程文件_{hash8}/`）及本轮的 `scenes`、`srt` 路径或 null。脚本不删除任何已有文件；同一视频重复运行会覆盖同名产物。

   命令必须成功退出后才能继续；抽帧或镜头检测失败时停止并报告错误，不把旧目录中的文件当作本轮成功产物。

2. **读 `{work_dir}/summary.md`**：时长、帧数、完整逐字稿、镜头统计、建议先看的帧。

3. **亲自看 5 张帧**（summary.md 列出的那 5 张：0 秒、2 秒、中段、四分之三处、结尾），用一次 Read 读完。确认画面与标题 / 逐字稿吻合。如果帧内容和预期严重不符（完全无关的场景），说明抽帧或文件搞错了，先排查。

4. **写画面描述摘要**：按时间段各一句话描述你看到的画面（例如「0–3 秒：泳池远景，无人物特写；3–7 秒：手持产品特写；…」），再写一条防幻觉检查点：「全片没有 XX 场景」。这两段会原样放进每个子 Agent 的 prompt。

5. 有脚本 / Brief 的话读一遍，记下这条视频原本要撬动的指标和固定要求。

## Phase 2：八维度并行诊断

用 Agent 工具在**同一条消息里**发出 8 个子 Agent，`model` 参数按「可调参数」设置。每个子 Agent 的 prompt 用下面的模板，只替换维度相关的三处：

```
你是抖音短视频「{维度名}」的专项诊断师。

先完整阅读这两个文件，然后严格按其中的流程和输出格式工作：
1. 公共规范：{本目录绝对路径}/references/diagnostic-common.md
2. 本维度 Skill：{套装 skills 目录绝对路径}/{专项目录名}/SKILL.md

素材：
- 过程目录：{work_dir 绝对路径}（帧图片、mapping.json、summary.md、scenes.json 都在这里）
- 本轮镜头统计 / 字幕：{预处理 JSON 的 scenes / srt 值；null 表示本轮不可用，不读旧文件}
- 逐字稿（带时间）：
{summary.md 中的逐字稿全文}
- 主 Agent 已核对的画面描述摘要：
{Phase 1 第 4 步写的摘要}
- 防幻觉检查点：{全片没有 XX 场景。如果你在帧里看到这些，说明读错了文件，停下来报告。}
- 脚本 / Brief 要点：{有则附，无则写"无"}
- 目标人群 / 本条想撬动的指标：{有则附}

按公共规范第 4 节「子 Agent 模式」输出，40 行以内。只返回诊断结果，不要复述素材。
```

| # | 维度名 | 专项目录名 |
|---|---|---|
| 1 | 前 2 秒跳出 | `sherry-douyin-kaitou` |
| 2 | 完播率 | `sherry-douyin-wanbo` |
| 3 | 点赞率 | `sherry-douyin-like` |
| 4 | 评论率 | `sherry-douyin-comment` |
| 5 | 收藏率 | `sherry-douyin-fav` |
| 6 | 转发率 | `sherry-douyin-share` |
| 7 | 视觉信息传达 | `sherry-douyin-shijue` |
| 8 | 文案表达质量 | `sherry-douyin-wenzi` |

**Agent 工具不可用或并发受限时**：按同样的顺序由主 Agent 逐个维度执行（每个维度读对应 SKILL.md 后按子 Agent 模式输出），不省略维度。

收齐 8 份结果后进入 Phase 3。如果某个子 Agent 报告「帧与摘要不符」，先核实再决定是否重跑。

## Phase 3：汇总与核心指标

1. **评分完整度**先统计为「已评分 X / 8」。8 个维度都有数值分时，**总评分** = 8 个分数的平均值，保留到 0.5。任一维度为 N/A 时，正式总评写「暂缺（证据不足）」；可附「已评维度均分」= 仅数值维度的均值（保留到 0.5），但明确它不代表完整总评。X = 0 时不计算均分。N/A 不作 0 分、不补估分、不混入分母。
2. **第一核心指标永远是「前 2 秒跳出」。**
3. **第二核心指标**按优先级确定：
   - 用户给了 Brief → 用 Brief 写明的设计意图（「清单教程→收藏」「身份标签→转发」等）
   - 用户口头指定 → 以用户为准
   - 都没有 → 在完播 / 点赞 / 评论 / 收藏 / 转发五个行为维度里选**已评分且得分最高**的那个（这条视频天然最擅长的方向，优先做到极致）。并列时按 收藏 > 转发 > 点赞 > 评论 > 完播。视觉传达和文案质量是执行维度，不参与这一步。五项全为 N/A 时写「待补证据后确定」。
4. 同时记下**已评分维度中得分最低的维度**，在内部报告里单独点出；全部为 N/A 时不选最弱维度，改列待补材料。

### 报告二：拍摄方修改指令（给达人 / KOC / 摄影团队，零术语）

读者只看「改哪里、改成什么、为什么」。

**取材规则**——从 8 份结果里收集需要改的问题：
- 前 2 秒跳出、视觉传达、文案质量：全部致命 + 严重错误
- 第二核心指标：全部致命 + 严重错误
- 其余行为维度：致命错误；严重错误只在影响明显时纳入
- 条数由问题数量决定，不凑数也不砍
- N/A 维度只列待补材料，不推断错误或编写修改动作

**写法**——按视频时间顺序排列，同一秒的改动合并为一条；每条 = 秒数 + 具体操作 + 1–2 句大白话原因 + 【剪辑改 / 需要补拍】，优先剪辑方案；写到拍摄方不用回来追问的粒度。禁用词表见公共规范第 5 节。

```
# {标题} —— 修改指令

总评：{X/5 或 暂缺（证据不足，已评分 X/8）} | {一句大白话概括已确认的问题；没有足够证据时写需补什么材料}

1. **第 0–1 秒**：把第 6 秒的清单卡画面剪到开头，字幕改成「泳池回来千万别直接冲水洗头！」。现在开头是泳池远景，刷到的人看不出这条跟自己有什么关系。【剪辑改】
2. **第 4 秒**：口播说「去氯洗沐」时，画面从泳池换成手拿产品的特写。嘴上说产品、画面还在泳池，观众不知道你在说什么东西。【剪辑改】
3. **第 9 秒**：「效果特别好」改成「用了 3 天氯味完全没了」。说具体天数和变化，观众才记得住。【需要补拍】
4. **第 11–13 秒**：口播在讲「等 2 分钟」，字幕和前后一样是普通白字。把「等 2 分钟」放大或换色，让人一眼看到这是关键步骤。【剪辑改】
5. **第 15 秒（结尾）**：加一句「你家宝宝游完泳一般怎么洗头？」。现在结尾直接断了，加个提问让看完的人有话想说。【剪辑改】

发布文案：
- 标题：{具体文字}
- 正文第一句：{具体文字}
```

## 质量标准

- 分数和结论来自子 Agent 的证据，不在汇总时"调分"。某维度写了「无法判断」就照实保留。
- 内部报告保留子 Agent 的原文；修改指令是你从中提炼并翻译成大白话的结果。
- 每条修改指令读完就能干活。写完自检：拍摄方会不会回来问"具体怎么弄"？会就补细节。
